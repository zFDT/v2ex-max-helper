# 常见问题（FAQ）

## Q1. 提示「无 Cookie」或签到显示「Cookie 已失效」

- 确认已执行过 `node v2ex-checkin.js --save-cookie` 并生成了 `~/.v2ex_cookie`。
- 若确已失效，重新登录 V2EX 复制最新 Cookie 再保存一次即可。
- 正常运行时登录态会自动续期、一般无需频繁重登，详见 [Q1b](#q1b-登录态会自动刷新吗还要经常重新登录吗)。开启 `--ping` 保活可进一步降低失效概率。

## Q1b. 登录态会自动刷新吗？还要经常重新登录吗？

**会自动刷新，正常情况下无需频繁重登。** V2EX 的 `A2` 登录 Cookie 是「滑动续期」的：
只要定期带着它访问，服务端就会通过响应的 `Set-Cookie` 下发续期后的新值，把有效期往后推。

本项目三条链路都会**自动捕获并写回**这个续期 Cookie，实现登录态自动延长：

| 链路 | 触发时机 | 自动续期 |
|------|----------|----------|
| 保活心跳 `--ping` | 每 6 小时 | ✅ |
| 每日签到 | 每天一次 | ✅ |
| 自动阅读 `reader/main.js` | 每次读帖（Playwright 自带） | ✅ |

**最佳实践**：配好 `--ping` 定时任务（每 6 小时一次），登录态即可长期自我维持，
通常只有在你**主动在别处退出登录**、或**长时间完全不运行**导致 Cookie 自然过期时，才需要重新保存 Cookie。

> 早期版本的保活只访问、不写回续期 Cookie，会导致 Cookie「白白自然过期」。现已修复。

## Q2. 阅读脚本报「Cookie 文件不存在或为空」

阅读模块与签到模块共用 `~/.v2ex_cookie`。先用签到模块的 `--save-cookie` 保存 Cookie。

## Q3. 无头服务器运行阅读脚本报错 / 浏览器起不来

`browser.js` 默认使用 headless 模式，无头 VPS 可以直接运行。先执行 `npx playwright install-deps chromium` 和 `npx playwright install chromium` 补齐系统库与浏览器内核。

只有显式设置 `HEADLESS=false` 时才需要 `xvfb`：

```bash
sudo apt-get install -y xvfb
HEADLESS=false xvfb-run -a node main.js
```

不建议直接修改源码切换模式；用 `HEADLESS=false` 即可临时测试有头模式。无论哪种模式都不能保证绕过站点风控。

## Q4. 遇到 Cloudflare 「Just a moment...」挑战

脚本内置检测与最多 60 秒等待（`waitForCloudflare`）。若频繁卡住：
- 降低阅读频率；
- 更换干净 IP 的 VPS；
- 检查系统时间、出口网络和 Cookie 是否正常；必要时用 `HEADLESS=false` 对比测试。

## Q5. Telegram Bot 没有反应

- 检查 `~/.v2ex_env` 中 `TG_TOKEN` 是否正确。
- 如果未填写 `TG_CHAT_ID`，必须先设置 `TG_SETUP_CODE`，重启 Bot 后私聊发送 `/bind <口令>` 完成绑定。
- Render 免费实例反复要求绑定通常是因为 `.telegram_chat_id` 位于临时文件系统，休眠、重启或重新部署后被清空。请在 Render Dashboard 的 Environment 中固定设置 `TG_CHAT_ID`；不要把真实 ID 写入仓库。外部 HTTP 保活不能替代持久授权配置。
- Bot 只响应已绑定的 Chat ID，用别的账号发消息会被忽略。
- 确认 `bot.js` 进程在运行（`systemctl status v2ex-bot`）。

## Q6. `/debug` 提示「日志文件不存在」

`bot.js` 默认读取运行时数据目录下的 `v2ex-reader.log`。请确认阅读脚本和 Bot 使用同一个 `V2EX_DATA_DIR`，
或在 `~/.v2ex_env` 中设置 `READER_LOG=` 指向你的实际日志文件。

## Q7. 余额一直不变 / 活跃度奖励没触发

- V2EX 活跃度奖励有自身规则与上限，并非读得多就一定加币。
- `MAX_CHANGE_COUNT` 默认为 2，达到即认为奖励已发完并停止，属正常行为。
- `/sou` 会显示最近一次余额读取失败原因；用 `node inspect_balance.js` 可打印 `/balance` 的 HTTP 状态、诊断结果和脱敏结构摘要，不输出原始页面。
- 如果诊断显示 Cloudflare/验证页，通常是当前 IP 或浏览器态被拦截，先降低频率或更换网络环境。

## Q8. 会不会泄露我的隐私？

- 代码中不含任何 Token、Chat ID、Cookie，全部来自本地配置文件或运行时绑定文件。
- `.gitignore` 已排除 `.v2ex_env`、`.v2ex_cookie`、`.telegram_chat_id`、`data/`、`chrome-profile/` 等敏感内容。
- 切勿把 `~/.v2ex_cookie`、`~/.v2ex_env` 或 `reader/data/` 上传到任何公开仓库。

## Q9. 如何配置飞书推送通知？（L1）

1. 飞书群 → 设置 → 群机器人 → 添加自定义机器人 → 复制 Webhook 地址
2. 安全设置选「自定义关键词」，填 `V2EX`
3. 将 Webhook 地址填入 `~/.v2ex_env` 的 `FEISHU_WEBHOOK` 变量
4. 签到、阅读完成等事件会自动通过飞书群推送

## Q10. 飞书机器人 @它不回复？（L2）

- 确认已按照 `docs/飞书应用机器人配置.md` 完成全部步骤
- 检查 `FEISHU_APP_ID` 和 `FEISHU_APP_SECRET` 是否正确
- 确认 `v2ex-feishu-bot` 服务运行中：`systemctl status v2ex-feishu-bot`
- 确认 6700 端口可被飞书服务器访问
- 仅响应 `/` 开头命令（`/help`, `/sou`, `/status`, `/debug`, `/stop`）

## Q11. 国内服务器无法访问 V2EX？

- 需要部署代理（如 Clash/Mihomo），参见 `DEPLOYMENT-GUIDE.md`
- 在 `~/.v2ex_env` 里设置 `V2EX_PROXY_ENABLE=1` 和 `V2EX_PROXY=http://127.0.0.1:7890`，
  代理由 `lib/config.js` 全局接管 `https.request`，仅对本项目进程生效，不影响服务器其他业务
- **手动运行时必须先加载环境**，否则代理不生效（请求会直连并超时）：

```bash
set -a; . ~/.v2ex_env; set +a
```

## Q12. 阅读任务报 `首页认证探针返回异常状态 (HTTP 403)`？

V2EX 部署在 Cloudflare 之后，这是**托管挑战**（响应头 `cf-mitigated: challenge`，
页面标题 `Just a moment...`），不是 Cookie 失效，也不是网络故障。

最常见的成因是 **User-Agent 里的 Chrome 主版本"尚未发布"**：`reader/fingerprint.js`
会取 Playwright 自带 Chromium 的真实版本拼 UA，而它长期领先于 Chrome 稳定版，
于是认证探针与 Playwright 浏览器会**同时**被拦，reader 在验证阶段就退出。

排查顺序：

```bash
# 1) 确认代理与 Cookie 正常（返回 200 就说明它们没问题，问题在 UA）
curl -s --proxy http://127.0.0.1:7890 -o /dev/null -w "%{http_code}\n" \
  -H "Cookie: $(cat /root/.v2ex_cookie)" https://www.v2ex.com/

# 2) 看响应头里的 cf-mitigated 是否为 challenge
```

处理：把 UA 主版本压到安全上限即可（2026-09 实测 Chrome/140+ 触发挑战，139 及以下正常）：

```ini
# ~/.v2ex_env
V2EX_UA_CHROME_MAX=139
```

## Q13. 告警里 `NRestarts` 很大、日志每分钟刷一次「未捕获错误」？

说明给 `v2ex-reader.service` 加了 `Restart=on-failure`。阅读任务本由
`v2ex-reader.timer` 每日驱动、进程内已有完整重试与看门狗，systemd 的自动重启
只会在被 Cloudflare 拦截时变成「每分钟一次」的风暴，反而加重封锁。

```bash
systemctl cat v2ex-reader.service     # 确认是否来自 *.service.d/restart.conf
# 正确做法：Restart=no，需要重跑时手动 systemctl start v2ex-reader.service
```
